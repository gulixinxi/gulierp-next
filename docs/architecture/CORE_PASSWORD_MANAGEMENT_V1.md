# Core 密码管理 V1

## 适用范围

ERP 与 CRM 共用 Identity Core 的本地账号、密码哈希、Cookie 会话和密码策略。CRM 不维护第二份账号或密码。现有账号的密码哈希继续有效；新策略只在设置新密码时生效。

## 已实现

- 新密码长度为 15–128 个字符，不强制大小写、数字或特殊字符组合；拒绝少量已知弱密码、包含 `changeme` 或包含用户名的密码。当前内置名单只是基础拦截，不等于完整的已泄露密码库。
- 用户菜单中的“修改密码”要求当前密码、新密码及确认输入。`POST /api/v1/auth/password/change` 要求已登录和有效 CSRF 令牌，并限制每个用户 15 分钟内最多 10 次请求。接口不返回密码。
- 修改成功后当前浏览器退出登录，其他 Cookie 会话由安全戳校验失效；校验间隔最长 1 分钟。旧密码不再可登录。
- 新开发库首次播种时，操作员须分别提供 `GULIERP_DEV_SEED_PLATFORM_ADMIN_PASSWORD` 和 `GULIERP_DEV_SEED_TENANT_ADMIN_PASSWORD`，两者必须不同且满足新策略。缺少时播种在写入前失败。已有数据库不会自动改密。
- 身份初始化工具中会设置密码的路径复用 Core 策略；只读诊断路径不变。

## 操作要求

在安全的本地环境注入两个播种环境变量，不要把值写入 `.env.example`、源码、提交、日志或工单。生产环境使用单独的凭据管理渠道。密码不应由管理员通过聊天工具传递。启动已有数据库无需设置播种密码；不要为了更新密码而重新播种或运行迁移。

## 第二阶段：管理员重置、首次改密、TOTP

- 拥有 `identity.user.manage` 权限的同租户管理员可在用户菜单按用户 ID 辅助重置。必须再次输入自己的密码；如管理员已启用 MFA，还须输入验证器码或一次性恢复码。不能重置自己、其他租户用户或平台管理员。服务端生成随机临时密码，响应只显示一次、禁止缓存，并记录操作人与目标 ID（日志不记录密码）。管理员须先核验申请人身份，再通过既定的安全渠道单独交付；系统没有内置短信或邮件发送。
- 新建用户和新开发库播种的管理员带有 `must_change_password` 声明。重置也会加上此声明，并通过安全戳撤销旧会话（最长 1 分钟）。登录后前端进入专用改密页，后端拒绝其访问业务 API。只有完成改密并重新登录后才可继续。既有账号不会被批量标记。
- 用户可在用户菜单通过当前密码获取 TOTP 绑定密钥，以验证器生成的 6 位码启用 MFA；启用时生成 8 个仅展示一次的恢复码。后续登录先校验密码，再校验 TOTP 或消耗一个恢复码。停用要求当前密码及 TOTP/恢复码。启用或停用后退出当前会话。
- TOTP 密钥由 ASP.NET Core Identity 保存于身份数据库；系统不会把它放在源码、客户端持久化存储或日志中。所有新写接口要求登录、CSRF 令牌及限流。

## 尚未覆盖

- 已存在账号的首次改密标记和历史弱密码清理需要单独的运营批次；本次没有批量修改已有账号或数据库结构。
- MFA 是用户自行启用的 TOTP；未实现管理员强制启用、WebAuthn/通行密钥、硬件密钥、独立恢复审核或外部凭据保管库。
